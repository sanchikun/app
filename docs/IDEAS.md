# リングタイマー アイデアメモ & ロードマップ

## 1. コンセプト

> **「見なくても使える、ひと目でわかる」タイマー**

- 手が離せないとき（料理・筋トレ・ストレッチ・作業中）に **声で操作し、声で知らせてくれる**
- 画面を見たときは **円グラフ（リング）1周 = 設定時間** なので、残りの量が直感でわかる
- 単発タイマーもインターバルも **同じ1つの画面** で扱う

## 3. 設計のポイント

### 「経過時間ベース」のエンジン
`setInterval` で1秒ずつ減らすと、ブラウザがバックグラウンドのタブを間引いたときに時間がずれる。
本アプリのエンジン（`src/core/engine.ts`）は **開始時刻からの経過時間** で状態を計算するので、
いつ描画しても正しい残り時間になる。スマホアプリ化したとき、アプリ復帰時の再計算や
「終了予定時刻に通知を予約」する処理にもそのまま使える。

### 単発もインターバルも同じ「プログラム」
単発タイマー = 「ステップ1つ × 1ラウンド」として扱い、エンジン・UI・読み上げを共通化している。

### 合図の判定は純粋関数
「いつ何を読み上げるか」は `detectCues(前回の状態, 今回の状態, 設定)` という純粋関数
（`src/core/announcer.ts`）で決める。ブラウザに依存しないのでユニットテストでき、
ネイティブアプリでも同じロジックを使える。

### プラットフォーム依存部分は `src/services/` に隔離
| ファイル | Web での実装 | スマホアプリでの置き換え候補 |
| --- | --- | --- |
| `speech.ts` | Web Speech API (speechSynthesis) | ネイティブ TTS（Capacitor: `@capacitor-community/text-to-speech`） |
| `recognition.ts` | Web Speech API (SpeechRecognition) | ネイティブ音声認識（`@capacitor-community/speech-recognition`） |
| `sound.ts` | Web Audio API でビープ生成 | 同じまま or ネイティブ音声 + Haptics |
| `wakeLock.ts` | Screen Wake Lock API | `@capacitor-community/keep-awake` |
| `storage.ts` | localStorage | `@capacitor/preferences` |

## 4. スマホアプリ化のロードマップ

### Step 1: Web 試作（いまここ）
- React + TypeScript + Vite の Web アプリ
- PWA 対応済み（ホーム画面に追加・オフライン起動）→ **この段階でもスマホで実用できる**

### Step 2: PWA として実機で使い込む
- iPhone Safari / Android Chrome で「ホーム画面に追加」して試用
- 音声認識の精度・誤反応、読み上げのタイミングを調整
- 気づいた点を IDEAS に反映

### Step 3: Capacitor でネイティブアプリ化（推奨）
同じ Web コードをそのままネイティブアプリに包める。

```bash
npm i @capacitor/core @capacitor/cli
npx cap init "リングタイマー" com.example.ringtimer --web-dir dist
npm i @capacitor/ios @capacitor/android
npm run build && npx cap add ios && npx cap add android
npx cap open ios   # Xcode で実機ビルド
```

ネイティブ化で解決したいこと:
- **バックグラウンド・画面ロック中の通知**: Web では画面ロック中に JS が止まることがある。
  → 開始時に「区間の終了時刻」すべてを **ローカル通知（`@capacitor/local-notifications`）で予約** し、
  一時停止・リセット時に取り消す。エンジンが経過時間ベースなので終了時刻は計算で求まる。
- **バックグラウンドでの読み上げ**: iOS はオーディオセッションを有効にしてバックグラウンド再生扱いにする。
- **iOS Safari の音声認識制限**の回避（ネイティブの SFSpeechRecognizer を使う）。
- バイブレーション（iOS の Web は非対応）→ `@capacitor/haptics`。

### 代替案: React Native / Flutter
UI をネイティブで作り直す必要があるが、`src/core/`（エンジン・合図判定・音声コマンド解析）は
TypeScript のまま React Native に持ち込める。描画性能やウィジェット対応が必要になったら検討。

## 5. 既知の制約（Web 版）
- 音声認識は Chrome / Edge / Safari で動作。Firefox は非対応（読み上げは動く）。
- 音声認識はブラウザによってはネットワーク経由で処理される。
- iOS Safari は、ボタンを一度押すまで読み上げ・効果音が鳴らない（ブラウザの仕様）。
- 画面ロック中・アプリ切り替え中は、端末によって読み上げが止まる（→ Step 3 で解決）。
